# P13 arm live: the gripper on Group 1's arm, in the browser

**Live demo (once Pages is on): https://jacob-rn-wallace.github.io/p13-arm-live/**

Spun out of the private MAE 451 Project 13 gripper repo (`sim/web/`, history kept). The model, scenes and demo data in `public/` are generated there by `sim/export_web.py`; this repo holds only what the page needs.

Live physics in the page: MuJoCo compiled to WebAssembly, drawn with three.js. The default page is **Connect 4, you against the arm** (click a column; the arm
answers by picking a red ball and dropping it into one; see the parent repo's `sim/README.md`). `?demo=sort` is the **ball-sort puzzle** (Randomize, Solve: three balls
sorted by size, the arm plans live). `?demo=firmware` runs the arm firmware's demo (one Ø100 ball shuttled between stand A and
stand B) as the firmware does it. Nothing is pre-recorded. Push the ball or the arm
while it runs and the physics responds. Same pattern as `conicoid-sim/web`.

## Run it

Needs Node 20 or newer and Python 3 (only to serve the files).

```
git clone <this repo> && cd <this repo>
npm ci          # first time only
npm run serve        # builds dist/ and serves it; open http://localhost:8765
```

| Control | |
|---|---|
| Pause | Space |
| Connect 4 | Click a column or press 1-7 (your ball); N new game; V next camera; buttons: who starts, Easy / Medium / Hard |
| Ball sort / firmware | R randomize (sort) or restart, S solve |
| ½× 1× 2× 4× | Playback speed. The clock shows the speed actually reached; it says so if the computer can't keep up. |
| Overview / Board / Hand / Side | Camera (*Board* is face-on, *Hand* follows the palm; keys 1 2 3 in the other demos, V in Connect 4) |
| Mouse | Drag to orbit, right-drag to pan, scroll to zoom, **Shift-drag** to push the ball or any part of the arm (a capped spring, 6 N max) |

## What it runs

| | From |
|---|---|
| Model | `public/scenes/p13_web.xml` + `assets/`: `sim/p13_arm.xml` (in the parent repo) made light by `sim/export_web.py`. Meshes decimated (228k to 51k triangles), screws/pins/nuts not drawn (their mass kept), only the hand, ball, stands and floor collide. |
| Demo | `public/demo.json`: the table in `main.cpp`, `q_0`, `moveJointsTo()`'s speed limits and the gripper / timing spec, read from the mae451-arm submodule by `sim/firmware.py` |
| Connect 4 | `public/scenes/p13_connect4.xml` + `connect4.json` (`sim/export_connect4.py`); `src/connect4.js` rules and opponent, `src/c4plan.js` the arm's drop, `src/c4sim.js` the ball pool, `src/c4game.js` the turns |
| Logic | `src/demo.js`: a port of `sim/run_demo.py`'s emulation (shared trapezoidal profile, 300 ms pause, gripper CLOSE 4 s / OPEN 3 s with the stall-and-hold behaviour). It loops forever, like `loop()`. |

**Checked:** `node test_connect4.mjs [robotMoves|full] [seed] [level]` (rules, opponent, planner, games in physics; `npm test` runs 2 arm moves). `npm test` (`test_demo.mjs`, headless in Node) runs one loop and compares every row end with the Python replay of
the same model (`public/reference.json`): arm joints within 0.003°, gripper link 1 within 0.01°, the ball within 0.1 mm, row
times within the 10 ms log step. Physics runs at about 13× real time in Node's WebAssembly on the machine it was built on. In
Chrome (software rendering, no GPU) the page held 1× and reached 1.6× at the 4× setting; with a GPU, drawing is cheap.

## Hosting

A push to `main` runs `.github/workflows/pages.yml`: `npm ci`, `npm test`, `npm run build`, then deploys `dist/` to GitHub Pages. One-time setup: repo **Settings → Pages → Source: GitHub Actions**. The page uses relative URLs only, so it works under `/<repo>/`. No server-side code or special headers are needed.

## After a change (in the parent repo)

- Gripper CAD, DH values: `sim/build_model.py`, then `sim/export_web.py`.
- Firmware table or speeds (mae451-arm): `sim/export_web.py` only.
- Then `npm test` and `npm run serve`.

`dist/` and `node_modules/` aren't in git. `public/` is: it's generated by `export_web.py`, but committed so the page builds without
the Python/CadQuery toolchain. Regenerate it in the parent repo and copy `sim/web/public/` here.

Same limits as the Python sim (`sim/README.md`): estimated arm masses, joints that never skip or stall, MuJoCo's soft contact.
